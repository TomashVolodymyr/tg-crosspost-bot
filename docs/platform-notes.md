# Нюанси платформ

Обмеження Telegram і Facebook, які визначають дизайн бота. Значення лімітів — з офіційної документації станом на жовтень 2026; перед релізом перевірити, чи не змінились.

## Telegram Bot API

### Що бот бачить
- У каналі бот отримує `channel_post` і `edited_channel_post`, лише якщо він адміністратор цього каналу. Чужий канал ботом не прочитати — для цього `MtprotoSource`.
- Видалення постів у каналі Bot API боту не повідомляє. Синхронізацію видалень можна зробити лише через MTProto.
- Коли бота додають у чат, змінюють йому права чи видаляють, приходить `my_chat_member`. На ньому будується реєстрація напрямків: бот бачить, що став адміністратором, і пропонує адміну додати чат.
- Щоб публікувати в канал, боту потрібне право «Публікація повідомлень»; у групі — достатньо бути учасником, але адміністратором надійніше (обмеження повільного режиму на адмінів не діють).

### Ліміти
- Не частіше одного повідомлення на секунду в один чат, не більше двадцяти на хвилину в одну групу, близько тридцяти на секунду загалом.
- Перевищення — помилка 429 з `parameters.retry_after` у секундах. Плагін `@grammyjs/auto-retry` чекає і повторює сам; поверх нього воркер тримає власний пейсинг, щоб до 429 доходило рідко.
- Текст повідомлення — до 4096 символів, підпис до медіа — до 1024. Пост, що після правил став довшим, обрізається з позначкою в журналі, а не падає.
- Через стандартний сервер Bot API бот завантажує файли до 20 МБ і відправляє до 50 МБ. Медіа, більше за ліміт, позначається `SKIPPED` з причиною.

### Альбоми
- Альбом — це від 2 до 10 окремих повідомлень з однаковим `media_group_id`, і бот отримує їх окремими оновленнями без ознаки «останнє».
- `AlbumBuffer` тримає частини альбому і передає їх далі, коли після останньої частини минуло `ALBUM_WAIT_MS` (за замовчуванням 1 500 мс).
- У `sendMediaGroup` підпис альбому — це підпис першого елемента; документи не змішуються з фото і відео в одному альбомі.

### Форматування і заміни
- Форматування передається масивом `entities` зі зсувами в одиницях UTF-16. Рядки в JavaScript теж індексуються в UTF-16, тому зсуви збігаються з індексами рядка, але емодзі займають дві одиниці — рахувати «символи» через `[...text]` не можна.
- Коли правило замінює фрагмент тексту, кожна сутність після нього зсувається на різницю довжин; сутність, що частково перетинає замінений фрагмент, обрізається або розширюється на новий фрагмент; сутність усередині заміненого фрагмента зникає. Це найризикованіша частина правил, тому вона покрита юніт-тестами першою.
- Посилання бувають двох видів: видимі в тексті (`url`) і приховані під словом (`text_link`, адреса лише в `entity.url`). Правило `REPLACE_LINK` змінює обидва.
- Телефони Telegram сам розмічає сутністю `phone_number`, але не завжди; правило `REPLACE_PHONE` шукає номери регулярним виразом у тексті, а не за сутностями.

### copyMessage
- `copyMessage` і `copyMessages` копіюють пост без заголовка «Переслано з», але не дають замінити текст текстового повідомлення (лише `caption` у медіа). Тому коли правила змінили текст, бот відправляє пост заново через `sendMessage` / `sendPhoto` / `sendMediaGroup` з тими самими `file_id`.
- `file_id` дійсний лише для бота, який його отримав. Медіа з MTProto-джерела бот бачити не може — воно завантажується через GramJS і відправляється як новий файл.

## Telegram MTProto (GramJS)

- Потрібні `api_id` і `api_hash` з my.telegram.org і сесія користувача (`StringSession`). Сесію створює окремий скрипт `npm run session:login` один раз: він питає номер, код і пароль 2FA і друкує рядок сесії для `.env`.
- Акаунт для сесії краще окремий: Telegram обмежує акаунти з підозрілою автоматизованою активністю, і основний акаунт не повинен від цього постраждати.
- Щоб отримувати оновлення каналу подіями, акаунт має бути його учасником. Для каналів, куди вступати не можна, запасний варіант — опитувати історію (`messages.GetHistory`) раз на `MTPROTO_POLL_INTERVAL_S`.
- Помилка `FLOOD_WAIT_X` означає чекати X секунд; клієнт GramJS частину таких очікувань виконує сам (`floodSleepThreshold`), довші треба обробляти явно.
- Видалення в каналі приходять як `UpdateDeleteChannelMessages` зі списком id.

## Facebook Graph API

### Що можна
- **Групи — ні.** Meta закрила Groups API у квітні 2024 року; сторонній застосунок більше не може публікувати в групи. Автоматизація особистого акаунта порушує правила Meta і закінчується блокуванням, тому бот цього не робить.
- **Сторінки — так**, від імені сторінки, з токеном доступу сторінки.

### Доступ
- Застосунок на developers.facebook.com, дозволи `pages_show_list`, `pages_manage_posts`, `pages_read_engagement`.
- Поки застосунок у режимі розробки, він працює для людей, які мають роль у застосунку, і для сторінок, якими вони керують. Для власної сторінки замовника цього достатньо; App Review потрібен лише для чужих сторінок.
- Токен сторінки, отриманий через довгостроковий токен користувача (`/me/accounts`), не має строку дії, але стає недійсним, якщо змінити пароль чи забрати в людини роль на сторінці. Покрокова інструкція — у [configuration.md](configuration.md).

### Публікація
- Текст і посилання — `POST /{page-id}/feed` з `message` і `link`.
- Одне фото — `POST /{page-id}/photos` з файлом (`source`, multipart) і `caption`. Через `url` Facebook сам завантажує файл, і адреса має бути публічною — для файлів із Telegram це не так, тому бот завантажує файл сам.
- Кілька фото — кожне через `/{page-id}/photos` з `published=false`, потім `POST /{page-id}/feed` з `attached_media[i]={"media_fbid":"<id>"}`.
- Відео — `POST /{page-id}/videos`; великі файли — через resumable upload.
- Форматування немає: жирний, курсив і `text_link` переводяться в простий текст, адреса з `text_link` дописується в дужках.

### Помилки
- `190` — токен недійсний: доставка `FAILED`, напрямок вимикається, адмін отримує повідомлення з інструкцією оновити токен.
- `368` — дію заблоковано як спам: `FAILED` без повторів.
- `4`, `17`, `32`, `613` — ліміти запитів: тимчасова помилка, повтор з затримкою.
