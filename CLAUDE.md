# CLAUDE.md — tg-crosspost-bot

Правила для Claude, який працює з цим репозиторієм. Власник і розробник — Володимир (GitHub `TomashVolodymyr`). Особисті нотатки лежать у `.claude/` (папка в `.gitignore`); на старті сесії, якщо є `.claude/CLAUDE.md`, прочитай його.

## Що це за проєкт

Бот публікує пост у кілька Telegram-чатів і на сторінку Facebook та переносить пости з каналу-джерела з правилами переписування. Огляд — [README.md](README.md), устрій — [docs/architecture.md](docs/architecture.md), обмеження платформ — [docs/platform-notes.md](docs/platform-notes.md). Перш ніж братися за тікет, прочитай його спеку в `docs/specs/` і розділ platform-notes, який вона згадує.

## Як ми працюємо з кодом

- Режим навчання: Володимир пише код сам, щоб розуміти проєкт. Claude не редагує код, а дає шматки коду й пояснення.
- Виняток — документація: `CLAUDE.md` і `docs/` Claude веде сам і оновлює разом з комітом тікета, у якому щось змінилось.
- Один крок — одна відповідь. Крок — один файл або одна невелика зміна; після кроку Claude чекає сигналу.
- До кожного шматка коду — дерево файлів: що створюється чи змінюється і де.
- Код функції чи методу — завжди повністю, від сигнатури до закривної дужки. Імпорти, константи й поля схеми — окремими повними рядками з місцем вставки.
- Перш ніж використати наявну функцію чи клас, Claude перевіряє в коді, що вони роблять, а не вгадує за назвою.
- API Telegram, GramJS і Facebook Claude не вгадує: якщо не певен у назві методу, параметрі чи ліміті, — каже про це і дає посилання на документацію для перевірки.
- Середовище — Windows і PowerShell; команди сумісні з PowerShell.

## Git

- `main` захищена: зміни лише через Pull Request із зеленим CI.
- Гілка на тікет від свіжого `main`: `feat/<N>-<коротко>`, `fix/<N>-<коротко>`, `docs/<коротко>`.
  ```powershell
  git switch main
  git pull
  git switch -c feat/7-publish-worker
  ```
- Коміти — conventional commits англійською з номером issue: `feat(delivery): add worker with row locking (refs #7)`. Заголовок до 72 символів.
- Опис PR — за шаблоном `.github/pull_request_template.md`: `fixes #N`, список змін, «Перевірено вручну: …». Claude дає його в блоці коду.
- Мердж — Squash and merge: один тікет — один коміт у `main`.

## Issues

- Кожен тікет з [docs/roadmap.md](docs/roadmap.md) — issue з тим самим номером; спека — у `docs/specs/<N>-<коротко>.md`, issue посилається на неї.
- Нова помилка чи доробка під час роботи — Claude дає текст для шаблону «Помилка» або «Доробка» по полях, у порядку форми; в тому самому PR її мовчки не виправляє.
- Жодних секретів (`BOT_TOKEN`, `TG_SESSION`, токени Facebook) в issues, PR, комітах і логах.

## Документація (`docs/`)

- `architecture.md`, `data-model.md`, `platform-notes.md`, `configuration.md`, `roadmap.md` — оновлюються в PR, який змінив те, що вони описують.
- `insights.md` — знахідки, які легко забути; Claude дописує їх сам.
- Спека потрапляє в `main` до початку роботи над тікетом.
