# AGENTS.md — tg-crosspost-bot

Правила для AI-агента, який працює з цим репозиторієм. Особисті нотатки лежать у `.claude/` (папка в `.gitignore`); на старті сесії, якщо є `.claude/CLAUDE.md`, прочитай його.

## Що це за проєкт

Бот публікує пост у кілька Telegram-чатів і на сторінку Facebook та переносить пости з каналу-джерела з правилами переписування. Огляд — [README.md](README.md), устрій — [docs/architecture.md](docs/architecture.md), обмеження платформ — [docs/platform-notes.md](docs/platform-notes.md). Перш ніж братися за тікет, прочитай його спеку в `docs/specs/` і розділ platform-notes, який вона згадує.

## Як ми працюємо з кодом

- Документація: `AGENTS.md` і `docs/` агент оновлює разом з комітом тікета, у якому щось змінилось.
- Перш ніж використати наявну функцію чи клас, агент перевіряє в коді, що вони роблять, а не вгадує за назвою.
- API Telegram, GramJS і Facebook агент не вгадує: якщо не певен у назві методу, параметрі чи ліміті, — каже про це і дає посилання на документацію для перевірки.
- Середовище — Windows і PowerShell; команди сумісні з PowerShell.

## Робота над тікетом

На запит «беремо тікет N» агент проходить увесь цикл сам:

1. Читає `docs/specs/<N>-*.md` і розділи `docs/`, на які спека посилається. Показує короткий план і чекає «ок».
2. Знаходить issue тікета в колонці «Issue» у `docs/roadmap.md`. Якщо issue ще немає, створює його через `gh issue create` з назвою тікета і посиланням на спеку, а номер вписує в roadmap у тій самій гілці.
3. Створює гілку від свіжого `main` за правилами розділу «Git».
4. Пише код і тести за спекою. Перед кожним комітом запускає `npm run lint`, `npm test` і `npm run build` (коли ці скрипти вже є) і виправляє помилки.
5. Комітить за правилами розділу «Git», без рядка `Co-Authored-By`.
6. Пушить гілку (`git push -u origin <гілка>`) і відкриває PR через `gh pr create` з описом за шаблоном `.github/pull_request_template.md`. Пункт «Перевірено вручну» залишає порожнім.
7. Дає посилання на PR і зупиняється. PR не мерджить.

## Доробка за рев'ю

На запит «доробка PR #N» агент читає коментарі рев'ю (`gh pr view N --comments` і `gh api repos/{owner}/{repo}/pulls/N/comments`), перемикається на гілку цього PR, виправляє зауваження, пушить у ту саму гілку і коротко пише, що змінено по кожному коментарю.

## Git

- `main` захищена: зміни лише через Pull Request із зеленим CI.
- Гілка на тікет від свіжого `main`: `feat/<N>-<коротко>`, `fix/<N>-<коротко>`, `docs/<коротко>`.
  ```powershell
  git switch main
  git pull --prune
  git branch -d docs/claude-workflow   # локальна гілка, PR якої вже змерджено
  git switch -c feat/7-publish-worker
  ```
- Коміти — conventional commits англійською з номером issue: `feat(delivery): add worker with row locking (refs #7)`. Заголовок до 72 символів.
- Опис PR — за шаблоном `.github/pull_request_template.md`: `fixes #N`, список змін, «Перевірено вручну: …». Агент створює PR з цим описом сам, як у кроці 6 розділу «Робота над тікетом».
- Мердж — Squash and merge: один тікет — один коміт у `main`.

## Issues

- Кожен тікет з [docs/roadmap.md](docs/roadmap.md) має issue, номер якого записаний у колонці «Issue». Номер тікета і номер issue можуть не збігатися, бо issues і PR на GitHub мають спільну нумерацію; спека — у `docs/specs/<N>-<коротко>.md`, issue посилається на неї.
- Нова помилка чи доробка під час роботи — агент створює issue за шаблоном «Помилка» або «Доробка» через `gh issue create`; в тому самому PR її мовчки не виправляє.
- Жодних секретів (`BOT_TOKEN`, `TG_SESSION`, токени Facebook) в issues, PR, комітах і логах.

## Документація (`docs/`)

- `architecture.md`, `data-model.md`, `platform-notes.md`, `configuration.md`, `roadmap.md` — оновлюються в PR, який змінив те, що вони описують.
- `insights.md` — знахідки, які легко забути; агент дописує їх сам.
- Спека потрапляє в `main` до початку роботи над тікетом.
